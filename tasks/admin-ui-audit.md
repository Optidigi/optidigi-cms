# Optidigi CMS UI audit

Reviewed release `63b6926`. The reviewer and tester used local standalone builds with disposable QA data. The tester inspected 61 screen and viewport combinations across 1280, 1024, 390, and 320 px. The audit covers component provenance and the content and interactions inside those components.

## Component rule

Use the official shadcn Base UI components available for the configured `base-vega` style. Install through the official registry, record the resolved source revision or checksum, and keep the generated primitive files intact. Compose those primitives in the CMS, using supported props, slots, and theme tokens. Payload auth, Lexical, upload inputs, preview iframes, and semantic HTML are infrastructure and document structure. shadcn supplies the controls around them.

A comparison of the 32 shared UI files with the current Base Vega registry found 19 exact matches after formatting and import alias normalization. The remaining 13 include icon and font-token substitutions and should be checked against generated output before calling them local rewrites. The clearest style mismatch is Select, which was imported from the chatbot template and has a different radius, height, and menu spacing from Base Vega. The confirmed app-level departures are direct Base UI styling in Preferences and Assistant Defaults, and handmade suggestion buttons.

Reference: [official registry](https://ui.shadcn.com/docs/registry), [Base Vega Select registry entry](https://ui.shadcn.com/r/styles/base-vega/select.json), [configuration](/home/serveradmin/src/optidigi-cms/components.json).

## Acceptance for component cleanup

1. Generate the desired versions in a clean directory with the repo's Base Vega configuration. Diff generated files before replacing shared primitives. Move presentation changes to feature composition or shared theme tokens.
2. Add a component-provenance check and an import rule to stop feature code from styling raw Base UI primitives. Allow documented application adapters and semantic elements. An official Native Select remains valid when it is the right control.
3. Verify light and dark at 320px, 390px and desktop widths. Exercise long names, English labels, keyboard navigation, focus restoration, mobile keyboard and floating-button overlap. Recheck persistence, context, draft and preview behavior when swapping controls.

The tester closed the browser, stopped its local server and removed the QA fixture. No application code or production state was changed.
